**Purpose:** Database design and testing specification for developers

## Overview

This document describes the **database schema**, **table relationships**, and
**data access methods** for THE TRACKERS application. It is intended as a
**developer-facing design document** that clearly defines how data is stored,
accessed, and validated.

This document answers the following questions:
- What are the tables you are going to have in the database?
- What are the fields of each table?
- What are the constraints for those table fields?
- What are the relationships between tables?
- What are the functions that will be created to access the database?
- What are the tests to make sure those access routines work?
- Which pages will need to access the database information?
- What are the tests to make sure the pages access the correct data in the database?
The backend uses **Supabase** accessed through **Prisma**

# Database Tables
The system requires the following tables:
- `user`
- `tracker`
- `tracker-post`
Each table is described below.
More tables may be added but for now these three will get us to our MVP.

---

## 1) Table: user

### Table Description

Stores user account and profile information for all TRACKER users, as well as links to their tracked data.

### Fields

| Field Name    | Description                | TYPE           | Constraints             |
|---------------|----------------------------|----------------|-------------------------|
| id            | id generated by app        | INT            | Primary key             |
| email         | users email                | STRING         | Unique                  |
| password      | Hashed password            | STRING         | NOT NULL                |
| name          | Name shown in UI           | STRING         | NOT NULL                |
| cuID          | id for cu for security     | STRING         | unique                  |
| trackerIDs    | The ids of user's trackers | STRING array   | NOT NULL                |
| created_at    | Account creation timestamp | DateTime       | NOT NULL, default NOW() |

### Relationships

- One-to-many with `tracker` via `trackerID` (as owner)
- Many-to-many with `trackerPost` through `tracker`

### Table Tests

**Use Case Name:** Create user record
**Description:** Verify a new user can be stored, edited, and deleted
**Pre-conditions:** Database running, binaries are set
**Test Steps:**
  1. Insert valid user row
  2. Query by email
  3. Edit name for test
  4. Delete user
**Expected Result:** User row exists, name is updated, user is then deleted
**Actual Result:** User returned by query, then new name is a part of the next query, finally user isn't returned by query
**Status:** Pass
**Post-conditions:** User can be persisted if not deleted

## 2) Table: Tracker

### Table Description
Represents a single tracking item for users. Currently we are working with only emotions for the moment.

### Fields
| Field Name    | Description                | TYPE              | Constraints             |
|---------------|----------------------------|-------------------|-------------------------|
| id            | id generated by app        | STRING            | Primary key, unique     |
| title         | the title of the tracker   | STRING            | String                  |
| trackerPosts  | Tracker Post Ids           | TrackerPost Array | NOT NULL                |

### Relationships
- Many-to-one with `users` via the id held in each user
- Many-to-many with `trackerPosts` via `trackerPostIDs`

### Table Tests
**Use Case Name:** Create a tracker for a user
**Description:** Verify the tracker is created
**Pre-conditions:** Owner user exists, server running, db running.
**Test Steps:**
1. Create a tracker for a user
**Expected Result:** Tracker row is created with an empty array of tracker posts
**Actual Result:** Tracker object returned
**Status:** Pass

---

## 3) Table: trackerPost

### Table Description
A Table showing the specific instance of a tracker post from the user.

### Fields
| Field Name   | Description                     | TYPE         | Constraints             |
|--------------|---------------------------------|--------------|-------------------------|
| id           | id generated by app             | String       | Primary key, unique     |
| rating       | feeling rating during that post | INT          | NOT NULL                |
| emotion      | emotion associated              | Emotion Type | NOT NULL                |
| trackerID    | id associated with post for ref | STRING       | NOT NULL                |
| recordedAt   | Post creation timestamp         | DateTime     | NOT NULL, default NOW() |

### Relationships
- Composite primary key (`userID`, `trackerID`)
- Is linked to a specific tracker that is linked to a user

### Table Tests
**Use Case Name:** Posted Emotion
**Description:** Verify tracker post creation
**Pre-conditions:** Owner user exists, server running, db running, tracker is created.
**Test Steps:**
  1. Enter values for rating and emotion associated
  2. Check to make sure the post got entered
**Expected Result:** Post exists
**Status:** Pass

# Data Access Methods
- Each table has at least one access method.
- Additionally data can be visually seen in supabase for devs

---

## Access Method: get_user_by_email
### Description
Fetches a user by email for authentication.
### Parameters
- email (string)
- password for verification
### Return Values
- User info, or null
### Tests
**Use Case Name:** Verify valid login
**Pre-conditions:** User exists, db running, server running
**Test Steps:**
  1. Sign in
  2. Check profile for valid information
**Expected Result:** User info returned
**Status:** Pass

---

## Access Method: Get Tracker data for User
### Description
Returns all trackers a user belongs to.
### Parameters
- user_id (int)
- trackerIDs
### Return Values
- List of trackers
### Tests
1. User with memberships logs in and creates a tracker
2. Nav to reports
3. User can see new tracker data
4. User with none returns empty list

---

## Access Method: Get post data for tracker associated with User
### Description
Returns tasks associated with a group.
### Parameters
- user_id (int)
- trackerIDs
- specific post id
### Return Values
- Post info
### Tests
1. User with memberships logs in and creates a post
2. Nav to reports
3. User can see new post data
4. User with none returns empty list
